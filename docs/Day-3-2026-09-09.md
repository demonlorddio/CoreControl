## What We Built

Today's work focused on three independent improvements that shipped as two commits:

1. **SubtitleWindow compacted** — the overlay text window was consuming too much screen space. Font dropped from 16→13 px, padding halved, line height tightened, and a 700 px max-width cap was added. The window now hugs its content instead of floating as a large box.

2. **HTML Message Logger** — a new `src/gui/message_logger.py` module records every conversation turn as JSONL and generates a live-updating HTML page. Opening it in any browser shows a dark-themed chat log with timestamped entries. A JavaScript poller compares file content and reloads when it changes, so you don't need to manually refresh.

3. **Python 3.14 SyntaxError fix** — embedding JavaScript inside a Python f-string tripped the 3.14 AST parser. The entire HTML was extracted into a static raw string constant (`TEMPLATE = r"""..."""`) and rendered via `str.format()`. JS braces are escaped as `{{` / `}}`. Zero behavior change; the generated HTML is identical.

## Bugs Fixed

### 1. Subtitle window too big
- **Symptom**: Subtitle overlaid on screen took up half the viewport.
- **Fix**: Reduced `QFont` size 16→13, halved padding (32→16 x, 16→8 y), line height from `fm.height() + 8` to `fm.height() + 4`, added `min(max_width_calc, 700)` cap.
- **File**: `src/gui/overlay.py` — `SubtitleWindow._update_size()` and `paintEvent()`

### 2. HTML logger not auto-refreshing
- **Symptom**: Browser showed stale content until user hit F5.
- **Root cause**: `<meta http-equiv="refresh" content="3">` is blocked by Chrome/Edge on `file://` URLs for security reasons.
- **Fix**: Replaced with a JavaScript `fetch()` poller that grabs the HTML file every 3 seconds, compares body text, and calls `location.reload()` only when content changed.
- **File**: `src/gui/message_logger.py` — `TEMPLATE` script block

### 3. Python 3.14 SyntaxError on HTML template
- **Symptom**: `SyntaxError: invalid syntax. Perhaps you forgot a comma?` at `var last = '';` — line 141 of `message_logger.py`.
- **Root cause**: Python 3.14's AST parser could not disambiguate JavaScript single quotes inside a complex f-string. The combination of JS syntax and the Python f-string conditional expression `message{'s' if total != 1 else ''}` confused the parser into treating JS code as a Python expression.
- **Fix**: Extracted the entire HTML into a module-level raw string constant (`TEMPLATE = r"""..."""`). Replaced f-string interpolation with `TEMPLATE.format(now=now, total=total, msg_word=msg_word, tbody=tbody)`. All literal JS/CSS braces escaped as `{{` and `}}`.
- **Verification**: `importlib.util` import check passes, test messages render correctly in the browser.
- **File**: `src/gui/message_logger.py`

## How It Works

### HTML Auto-Refresh
The generated `messages.html` contains this inline script:

```javascript
(function() {
  var last = '';
  var check = function() {
    fetch(location.href + '?t=' + Date.now())
      .then(function(r) { return r.text(); })
      .then(function(txt) {
        if (txt !== last) { last = txt; location.reload(); }
      })
      .catch(function() {});
  };
  setTimeout(check, 2000);   // first check after 2s
  setInterval(check, 3000);  // then every 3s
})();
```

Each poll fetches the HTML file with a cache-busting timestamp query param. If the returned text differs from the previously seen text, the page reloads — showing the new messages immediately. No server required.

### Thread Safety
`MessageLogger` uses a single `threading.Lock` around all read/write operations on `_entries`. `_write_jsonl()` and `_render_html()` are called *outside* the lock after releasing it, so the lock duration is minimal (just the append + copy). The JSONL file and HTML file are each written atomically per call.

### JSONL Format
Each line is one JSON object:
```json
{"ts": "17:20:55", "role": "user", "text": "hey wsp"}
{"ts": "17:21:08", "role": "assistant", "text": "Notice. Master has initiated contact..."}
```

## Configuration

No config changes required. The logger is wired up directly in `main.py`:

```python
from src.gui.message_logger import MessageLogger, get_html_path

_msg_log = MessageLogger()
_msg_log.reset()
```

The HTML page opens automatically on startup via `webbrowser.open()`. To view it later without restarting:

```powershell
Start-Process "file:///$(Get-Location)/logs/messages.html"
```

Or navigate directly to `logs/messages.html` in any browser.
