## What We Built

CoreControl is an AI Desktop Assistant that connects Telegram and voice input to local machine control via the Model Context Protocol (MCP). It can:

- Take screenshots and send them to Telegram
- Navigate web pages and return content
- Execute safe terminal commands
- Click coordinates and type text (with human-in-the-loop confirmation)
- Process voice messages via transcription
- Show a floating NPC overlay widget

## Bugs Fixed Today

### 1. Tool Calls Not Being Parsed (CRITICAL)
- **Symptom:** Bot responded with "Action completed" but never actually did anything
- **Root cause:** OmniRoute returns `tool_calls` on `choice.message.tool_calls`, not `choice.tool_calls`. Also, empty string arguments `""` failed JSON.parse.
- **Fix:** Changed to `getattr(choice.message, 'tool_calls', None)` and added empty-string handling

### 2. Screenshots Not Sent to Telegram
- **Symptom:** Screenshot tool executed (196KB response logged) but user received nothing
- **Root cause:** `process_prompt()` returned only a text string — screenshot bytes were discarded
- **Fix:** Created `ProcessResult` dataclass to carry `text`, `screenshots`, and `web_links`; updated Telegram bot to send photos via `send_photo()`

### 3. MCP Buffer Overflow
- **Symptom:** `ValueError: Separator is not found, and chunk exceed the limit`
- **Root cause:** asyncio default 64KB buffer too small for 196KB base64 screenshots
- **Fix:** Added `limit=1024*1024` (1MB) to `create_subprocess_exec()`

### 4. MCP Server API Compatibility
- **Symptom:** `TypeError: Server() takes no positional arguments`
- **Root cause:** Newer `mcp` library version changed API — decorators removed
- **Fix:** Switched to constructor callbacks: `Server(..., on_list_tools=..., on_call_tool=...)`

## How the Agentic Loop Works

```
User sends "take a screenshot" via Telegram
        │
        ▼
1. Take initial screenshot (context for LLM)
        │
        ▼
2. Select LLM engine:
   - Online: OmniRoute (localhost:20128) → OpenAI-compatible API
   - Offline: Ollama (localhost:11434) → fallback when no internet
        │
        ▼
3. Send prompt + screenshot to LLM with tool definitions
   LLM responds with text + optional tool_calls
        │
        ▼
4. For each tool call:
   a. Check HITL (Human-In-The-Loop) for high-risk tools
      → Send approval request to Telegram if needed
   b. Execute tool via MCP stdio
   c. Collect screenshot bytes if tool returns one
   d. Extract any URLs from response
        │
        ▼
5. Loop back to step 3 with tool results (up to 10 iterations)
        │
        ▼
6. Return ProcessResult(text, screenshots, web_links)
        │
        ▼
7. Telegram bot sends photos + text to user
```

## Configuration (config/settings.json)

- **Telegram:** Bot token, whitelist (user IDs), HITL timeout (300s)
- **OmniRoute:** API base URL (`http://localhost:20128/v1`), model selection (`"auto"` = use gateway default)
- **Ollama:** Local fallback at `localhost:11434`, model `qwen2.5-coder:7b`
- **Security:** Terminal command whitelist/blacklist, HITL required for click/type/terminal
- **Overlay:** Position (x=100, y=100), always-on-top
- **Audio:** 16kHz mono, VAD threshold 0.5, whisper base.en model

## How to Run

```bash
# 1. Start OmniRoute (self-hosted AI gateway) on port 20128
# 2. Start Ollama locally (optional, for offline fallback)
ollama serve

# 3. Install dependencies
pip install -r requirements.txt

# 4. Set your bot token in config/settings.json
# 5. Run the assistant
python main.py
```
